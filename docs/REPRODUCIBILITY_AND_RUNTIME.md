# Воспроизводимость и рабочие процессы

## Единственный контур выпуска

Исходная ревизия собирается из этого репозитория и разворачивается в
`/opt/grant-radar`. `scripts/deploy_qaz_fund.sh` отказывается работать с
незафиксированными изменениями, передаёт точную ревизию образу, ждёт готовности
API и сверяет эту ревизию через публичный домен.

Перед выпуском обязательны:

```bash
make lint
make ci-fast
python -m scripts.production_smoke --base-url https://qaz.fund
```

Миграции Alembic выполняет только контейнер API. Контейнер сбора данных получает
`GRANT_RADAR_SKIP_MIGRATIONS=1`, поэтому два процесса не меняют схему
одновременно.

## Разрешённые постоянные службы

| Служба Compose | Назначение | Постоянная |
| --- | --- | --- |
| `db` | PostgreSQL и постоянный том `pgdata` | да |
| `api` | FastAPI, публичные страницы и программный интерфейс | да |
| `worker` | Один планировщик обхода зарегистрированных источников и один обработчик очереди | да |

Другие контейнеры, процессы Python, пользовательские задания `cron` и таймеры
`systemd` для QAZ.FUND не требуются. Telegram, резервное копирование, выпуск и
обслуживающие проверки запускаются явными командами, если закрытый регламент
не закрепляет иное.

Даты окончания программ и понятие «сегодня» рассчитываются в часовом поясе
`Asia/Almaty`. Его можно явно задать через `GRANT_RADAR_TIME_ZONE`; Compose
передаёт то же значение как системный `TZ` в API и планировщик. Публичная
панель также использует этот пояс независимо от местного времени посетителя.

## Быстродействие и устойчивость

Контейнер API по умолчанию запускает два рабочих процесса Uvicorn. Это позволяет
обслуживать проверку готовности и короткие запросы, пока второй процесс формирует
крупную выгрузку. Значение меняется через `WEB_CONCURRENCY`, но производственный
минимум без отдельного обоснования – два процесса.

Нормализация, ранжирование, версия машинной записи и аналитический снимок
повторно используются внутри каждого рабочего процесса. Основной срок жизни
снимка задаёт `PUBLIC_ITEMS_CACHE_TTL_SECONDS`, аналитика обновляется не реже
значения `INSIGHTS_CACHE_TTL_SECONDS`. Готовые NDJSON-ответы хранятся в
ограниченном буфере из восьми вариантов. Обновление каталога очищает все эти
буферы. Внешняя служба кэширования и отдельный фоновый процесс для них не нужны.

Планировщик остаётся единственным процессом сбора. Одновременно он обходит не
более четырёх источников, если
`GRANT_RADAR_MAX_SOURCE_CONCURRENCY` не переопределён. Файл жизнеспособности
обновляется тем же циклом событий, а проверка Compose переводит контейнер
`worker` в состояние `unhealthy`, если отметка не менялась две минуты. Это
контроль зависания, а не дополнительный планировщик.

После некорректной остановки новый рабочий процесс завершает прежние
незакрытые записи того же источника со статусом ошибки, а затем открывает
новую запись. История сохраняется, но старые запуски больше не выглядят
действующими.

Повторяемое измерение публичных маршрутов:

```bash
python -m scripts.performance_smoke \
  --base-url https://qaz.fund \
  --samples 5
```

Сравнивать нужно прогретую медиану каждого маршрута с предыдущим выпуском на том
же узле. Жёсткий предел задаётся через `--max-warm-ms` только в одинаковой
сетевой среде.

## Проверка рабочей среды

Команды не раскрывают значения переменных или секретов:

```bash
./scripts/audit_runtime.sh

# Равнозначная ручная проверка:
docker compose --env-file .env.prod \
  -f docker-compose.yml -f docker-compose.prod.yml ps
docker ps --filter label=com.docker.compose.project=grant-radar
ps -eo pid,ppid,lstart,command | grep -E 'grant-radar|core.scheduler'
crontab -l
systemctl list-timers --all
ss -lntp
```

Для каждого найденного процесса нужно определить владельца, команду запуска,
рабочий каталог и необходимость. Неизвестный процесс сначала останавливают
обычным способом и проверяют влияние; удаление выполняют только для точно
определённой устаревшей службы.

## Восстановление

До миграции создаётся резервная копия PostgreSQL вне репозитория. При заданном
`BACKUP_GPG_RECIPIENT` скрипт шифрует архив GPG; без получателя он создаёт файл с
правами 0600 и предупреждает об отсутствии шифрования. Проверка включает
ненулевой размер, контрольную сумму SHA-256 и, для зашифрованного файла,
`gpg --list-packets`. Практическая готовность к восстановлению подтверждается
отдельным испытанием на временной базе.

Том PostgreSQL нельзя удалять командами `docker compose down -v`, `docker
volume prune` или очисткой каталога развёртывания.

## Условия закрытия выпуска

- локальные тесты, проверка типов, стиля и мёртвого кода прошли;
- миграция поднимает чистую базу до `head`;
- контейнеры `db`, `api` и `worker` находятся в состоянии `healthy`;
- публичные `/health`, `/ready` и `/.well-known/release.json` отвечают;
- публичная ревизия совпадает с отправленной ревизией Git;
- прогретые показатели не ухудшились относительно зафиксированного замера;
- основные страницы проверены в настольном и мобильном размерах;
- повторный аудит не обнаруживает лишних процессов и расписаний.
