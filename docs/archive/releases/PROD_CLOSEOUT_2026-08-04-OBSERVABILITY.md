## Что исправлено

Парсеры сохраняют устойчивый контракт: сетевой сбой не останавливает worker и
не обрывает остальные источники. До этого такой сбой мог остаться в логах, а
запуск — ошибочно попасть в историю как успешный. Для этого добавлен единый
`last_fetch_error`: scheduler сохраняет запуск со статусом `error`, не публикуя
ложный успешный результат. Маркер подключён ко всем зарегистрированным
адаптерам; первым реальный случай был обнаружен на UNDP Procurement, после
релиза такой же сигнал подтвердился на UNICEF (HTTP 403).

Успешный запуск и отсутствие новых записей по-прежнему считаются нормальным
состоянием. Ошибка транспорта и ошибка разбора отделены от пустой выборки.

Полные массовые параллельные прогоны для текущего одиночного API не считаются
безопасным способом проверки; для релизов используется последовательный набор
маршрутов с ограничением нагрузки.

## Остаточный риск

Публичная свежесть источника считается по последнему успешному запуску и может
оставаться `fresh` в пределах допустимого окна после отдельного сбоя. Поэтому
операторская проверка должна учитывать оба сигнала: `coverage` для давности
данных и `operator/health` для последних ошибок запусков. Это разделение
сохранено намеренно, чтобы кратковременный сбой не скрывал ранее проверенные
данные от посетителей и одновременно не терялся в операторском контуре.
