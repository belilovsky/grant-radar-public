# Суточный выпуск для Telegram

QAZ.FUND формирует выпуск из неизменяемого журнала наблюдений. В него входят
только карточки, впервые замеченные или содержательно изменившиеся за выбранный
период. Повторный обход источника без изменения данных не создаёт событие.

## Публичные представления

- `/media/v1/digest/daily.json?lang=ru&hours=24`
- `/media/v1/digest/daily.txt?lang=ru&hours=24`

До накопления первого снимка ответ имеет состояние `collecting`. При отсутствии
изменений – `no_changes`. Отправитель не заменяет эти состояния выдуманным
содержанием.

## Предварительный просмотр

Команда по умолчанию ничего не отправляет:

```bash
python -m scripts.publish_telegram_digest \
  --base-url https://qaz.fund \
  --lang ru
```

## Явная отправка

```bash
export QAZFUND_TELEGRAM_BOT_TOKEN='server-only value'
export QAZFUND_TELEGRAM_CHAT_ID='target chat'

python -m scripts.publish_telegram_digest \
  --base-url https://qaz.fund \
  --lang ru \
  --state-file /var/lib/qazfund/telegram-digest-state.json \
  --send
```

Файл состояния не допускает повторной отправки одинакового выпуска. `--force`
обходит эту защиту, а `--send-empty` разрешает сообщение без новых событий.
Оба параметра применяются только вручную.

Скрипт не создаёт `cron`, таймер `systemd`, демон или фоновую задачу. Если
автоматическая доставка будет утверждена, её расписание, владелец, журнал,
секреты, повторные попытки и процедура отключения должны появиться в закрытом
эксплуатационном регламенте до активации.
